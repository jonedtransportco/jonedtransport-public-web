# 02A.21 First Public Intake Review Transition Plan — Drivers v1.0

Version: 1.0  
Lifecycle: Under_Review  
Authorization state: AUTHORIZED FOR PUBLIC INTAKE REVIEW-TRANSITION PREPARATION ONLY

## Objective

Prepare the first public route of `jonedtransport.com` for a future controlled transition from mock mode to approved real backend consumption in a review environment only, without activating production and without enabling any other public route.

## Selected first route

Selected route: `Drivers`

## Selection rationale

`Drivers` is the lowest-risk public route currently available for future review-environment backend transition because:

- it is already isolated as a dedicated public route;
- it is narrower than `Owner Operators`;
- it is currently constrained to the no-vehicle driver intake path;
- it avoids the wider conditional surface of owner-operator authority, vehicle, insurance, and payment permutations;
- it is already represented as a mock step-based flow with explicit route resolution;
- it can be prepared without authorizing real operational onboarding or portal-side activation.

`Owner Operators` remains a later candidate after the first public review-transition pattern is proven on a smaller route.

## Traceability inside `02A`

- aligns with `02A.07_Backend_Integration_Readiness_Mapping_and_API_Consumption_Transition_Plan_v1.0.md`
- preserves the controlled-stop boundary established in `02A.09_Reportes_Real_API_Review_Activation_Controlled_Stop_Report_v1.0.md`
- extends the public `Drivers` implementation line regularized in `02A.18` and `02A.19`
- remains compatible with the public homepage separation regularized in `02A.20`

## Current mock contract

Current public `Drivers` route behavior:

- route selection by applicant type and license path;
- mock route resolution for:
  - `P3`
  - `P4`
  - `B3`
  - `B4`
- mock-only helper text and checklist visibility;
- no persistence;
- no real upload;
- no real submission endpoint;
- no portal workflow activation.

## Future target contract

Future review-environment backend contract should remain strictly limited to:

- route classification input;
- applicant profile intake payload;
- read-safe validation feedback;
- canonical submission acknowledgement;
- non-operational review status response.

Not authorized for the first switch:

- production activation;
- owner-operator route activation;
- document storage activation;
- dispatch or onboarding activation;
- portal-side operational workflow triggering;
- approval automation;
- payments, HR, Graph, SharePoint, or driver telemetry runtime coupling.

## Frontend adapter boundary required

The public route now has a documented review-transition boundary in:

- `app/public-intake-transition.ts`

Prepared switch model:

- top-level flag: `PUBLIC_INTAKE_API_MODE=mock|api-real`
- domain flag: `PUBLIC_INTAKE_DRIVERS_SOURCE=mock|api-real`
- reserved endpoint variable: `PUBLIC_INTAKE_DRIVERS_API_URL`
- non-selected domain remains mock:
  - `Owner Operators` must remain mock

Switch strategy:

`env-flag + domain allowlist + contract parity checks + mock fallback`

## Expected error and state handling

The first future review switch should preserve existing UX-state discipline:

- `loading`
- `error`
- `partial`
- `retry`
- `mock fallback`

Minimum future error taxonomy:

- endpoint missing
- unauthorized review environment
- upstream unavailable
- contract parity failure
- validation rejection
- empty response

## Acceptance criteria for the first future switch

The future first switch for `Drivers` may proceed only if all of the following exist:

1. approved review-environment endpoint URL;
2. approved canonical request and response specimen;
3. approved route-code parity for `P3/P4/B3/B4`;
4. review-only environment flag injection;
5. explicit confirmation that `Drivers` is the only public route allowed in `api-real`;
6. regression validation for desktop and mobile;
7. reversible mock fallback confirmed.

## Dependencies, gaps, and risks

### Dependencies

- approved review endpoint
- approved canonical response contract
- review-environment configuration authority
- domain-scoped activation decision from `00.2`

### Gaps

- no public intake API adapter implementation exists yet
- no public intake canonical error envelope exists yet
- no backend contract specimen exists in the current evidence line
- no review runtime variables are configured for public intake

### Risks

- premature coupling to operational onboarding
- accidental widening from `Drivers` to `Owner Operators`
- field drift between mock route model and backend route codes
- enabling write semantics before review-only validation is stable
