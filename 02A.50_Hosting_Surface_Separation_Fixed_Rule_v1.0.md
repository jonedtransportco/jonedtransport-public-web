# 02A.50 — Hosting Surface Separation Fixed Rule v1.0

## Status

Fixed rule adopted and written into the project baseline.

## Purpose

Prevent future mix-ups between the official production surfaces and any temporary review or preview surface.

## Fixed rule

- Public website: GitHub-hosted public repository only, with `jonedtransport.com` as the public-facing target.
- Private portal: Azure-hosted private portal only, with `portal.jonedtransport.com` as the portal target.
- Temporary preview hosts, review-only domains, and internal publishing endpoints are non-normative.
- temporary preview and review hostnames must not appear as official production targets in future project documentation, DNS instructions, or deployment decisions.
- Public and private experiences remain separate by design and by publication target.

## Evidence written

- `README.md`
- `ARCHITECTURE.md`

## Validation performed

- Project-wide search for temporary preview host references returned no matches in `work/02a-portal-web`.
- The project baseline documents were updated to state the official public and private hosting split.
- No application routing, identity, data, or backend behavior was changed by this rule update.

## Result

The hosting boundary is now documented as a fixed project rule.
