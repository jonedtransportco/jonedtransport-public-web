# 02A.11 Reportes Functional Contract Closure v1.0

Version: 1.0  
Lifecycle: Under_Review  
Authorization state: AUTHORIZED FOR FUNCTIONAL CONTRACT CLOSURE ONLY

## Objective

Close the functional contract for the `Reportes` domain in the portal review baseline, preserving the approved mock architecture and the future transition boundary already defined in `02A.07`, `02A.08`, `02A.09`, and `02A.10`.

## Closure decision

Functional contract status: `CLOSED FOR MOCK/REVIEW BASELINE`

This closure confirms that the frontend functional behavior for `Reportes` is sufficiently specified, internally consistent, role-aligned, and traceable for continued review use in mock mode.

This closure does not authorize:

- real backend activation;
- production opening;
- export execution;
- scheduling execution;
- writeback behavior;
- activation of any domain other than `Reportes`;
- any connection to real operational systems.

## Traceability

This closure is based on the following approved `02A` evidence chain:

- `02A.06` normalized the mock/API contract boundary and envelope expectations.
- `02A.07` established the transition strategy: `environment flag + adapter registry + contract parity checks`.
- `02A.08` selected `Reportes` as the first low-risk domain and defined the mock-to-future mapping.
- `02A.09` confirmed that real activation remains blocked because no approved review backend endpoint or canonical real contract was available.
- `02A.10` published visual and functional evidence for `Reportes` by role in the review environment.

## Functional contract closed

### Domain identity

- Domain name: `Reportes`
- Title: `Decisiones con perspectiva`
- Current source mode: `mock`
- Reserved future source: `Reporting API`
- Review boundary endpoint: `/api/v1/reports`
- Current fixture set: `insights-catalog.v2`
- Request shape: `ReportWorkspaceQuery`
- Response shape: `ReportWorkspace`
- Cache key: `reports-workspace`

### Closed functional scope

The following behavior is now closed for the review baseline:

- report catalog visualization;
- report summary metrics;
- role-based domain visibility;
- persistent filters for audience, periodicity, and domain;
- internal tabs `Catálogo`, `Widgets`, and `Programación`;
- list/detail rendering under `ready`, `partial`, `empty`, `error`, and `loading`;
- adapter-governed future switch boundary;
- role-conditioned action visibility under current mock state;
- controlled fallback from future `api-real` path to mock-safe behavior.

### Role closure

| Role | Visibility | Closed functional expectation |
| --- | --- | --- |
| Administración | Visible | Can consume list/detail and see `Solicitar reporte` in mock mode |
| Operaciones | Visible | Can consume report catalog and detail states with request affordance only |
| Human Resources | Visible | Can consume report catalog and detail states with request affordance only |
| Executive read-only | Visible | Can consume read-only views and see `Exportar vista` as visual-only mock affordance |
| Drivers | Not visible | `Reportes` remains absent from driver-facing navigation |

### Closed action behavior

| Action | Functional closure |
| --- | --- |
| `Solicitar reporte` | Mock-visible only, non-operational |
| `Abrir dashboard` | Read-oriented affordance reserved for ready state |
| `Exportar vista` | Visual-only mock affordance; not authorized for real export generation |
| `Programación` tab | Present as non-operational review state only |

### Closed state behavior

| State | Closed expectation |
| --- | --- |
| `ready` | Full catalog and widgets available in the existing normalized layout |
| `partial` | Catalog remains usable with explicit incomplete coverage messaging |
| `empty` | Zero-result rendering remains valid and distinct from error |
| `error` | Controlled error rendering remains within the approved envelope boundary |
| `loading` | Transitional loading state remains bounded to frontend fetch lifecycle |

## Consistency checks closed

The following consistency conditions are now considered closed for the mock/review baseline:

- mock contract, frontend domain configuration, and role evidence remain aligned;
- `Reportes` visibility is coherent with the approved role matrix;
- current actions are coherent with role permissions and mock-state gating;
- future `api-real` route remains isolated behind explicit flags;
- no functional dependency on financial runtime, document runtime, Graph, or production services exists in the closed baseline;
- the frontend preserves the one-domain transition path without activating it.

## Remaining open items outside this closure

The following items remain intentionally open and are not part of this functional closure:

- approved real Reporting API endpoint;
- approved canonical real response contract;
- backend authorization model for read-only reporting access;
- real export behavior;
- real scheduling behavior;
- analytical status taxonomy governance;
- production activation.

These open items belong to the later real-integration phase and must not be inferred as approved by this closure.
