# 02A.02 Design System v1.0

## Scope

This document governs the visual and structural layer of the JONED Web Portal foundation for work package 02A.02. It uses simulated data only and defines reusable interface rules for future API integration.

## Foundations

- Typography: Geist Sans for product UI, compact headings for dashboards and modules, no viewport-scaled body text.
- Color: navy primary shell, orange action/accent, blue informational states, mint success states, amber warning states, neutral white surfaces.
- Spacing: 4 px control radius, 6-8 px cards and panels, consistent 15-24 px panel spacing, fixed-height navigation rows.
- Iconography: shared inline icon set for navigation, status, search, route, security, and locked interface states.
- Layout: public portal, authenticated dashboard, and internal modules share the same brand system, panel treatment, data-note footer, and simulated environment markers.

## Reusable Components

- Cards: stat cards, module cards, access cards, and contract cards use a shared border, radius, and hierarchy.
- Tables: header and row grid structure supports responsive hiding of non-critical columns.
- Forms and filters: search field, period selector, and filter chip are consistent across dashboard and modules.
- Badges: success, warning, info, and mock error states are available as reusable visual tokens.
- Modals: permission review dialog is interface-only and does not perform authorization.
- Navigation: role switcher, visible modules, and locked module rows are reusable for future policy binding.
- Empty/loading/error states: deterministic local states are visible without external calls.

## Role-Based Navigation Readiness

The role model is mock-only and prepares the interface for later API authorization. UI visibility must never be treated as final authorization. Future services must enforce permissions server-side.

Roles covered:

- Administration
- Operations
- Human Resources
- Drivers
- Executive read-only

## Non-Operational Confirmation

No Azure SQL, Microsoft Graph, email, operational SharePoint, intake pipeline, payments, Gusto, PNC, OneRail, Frayt, ELD, or other real integration was connected for this package.

## Readiness

02A.02 is ready for Architecture Office review as a visual design-system and role-navigation hardening package. It is not authorized for operational use.
