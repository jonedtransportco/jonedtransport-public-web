# 02A.27 Private Portal Azure Migration Plan v1.0

Version: 1.0  
Lifecycle: Under_Review  
Authorization state: AUTHORIZED FOR PRIVATE PORTAL AZURE MIGRATION PLANNING ONLY

## Objective

Define the recommended migration path for `portal.jonedtransport.com` from the current temporary restricted hosting surface into the paid Microsoft platform stack already aligned with the JONED project.

## Recommended target

Recommended target for the private portal:

- hosting: Azure
- identity: Microsoft Entra ID
- domain: `portal.jonedtransport.com`
- access model: private or controlled access only

## Recommended platform pattern

Primary recommendation:

- Azure Static Web Apps
- Microsoft Entra ID authentication
- route and role protection for private portal surfaces

Alternative when heavier backend/runtime needs appear:

- Azure App Service
- Microsoft Entra ID authentication
- private app pattern with future API/runtime expansion

## Why this is recommended

- uses the Microsoft platform already planned and paid for
- removes dependence on ChatGPT/Sites as the long-term private hosting target
- gives cleaner enterprise control over identity, access, domain, and runtime
- keeps the public website and private portal fully separated
- aligns better with future internal API, document, and corporate integration patterns

## Scope to preserve during migration

The migration must preserve:

- `portal.jonedtransport.com` as private only
- role-based portal experience
- internal review surfaces
- current frontend boundary between portal and public site
- no forced change to `jonedtransport.com` public website

## Scope explicitly excluded

This migration plan does not authorize:

- public website migration into the private portal host
- backend production activation
- Azure SQL production connection
- Graph operational activation
- document runtime activation
- payment or payroll runtime activation

## Controlled migration sequence

1. create separate Azure target for the portal
2. bind Microsoft Entra ID authentication
3. restrict access to approved internal users or groups only
4. publish the private portal build to Azure
5. attach `portal.jonedtransport.com` to Azure private portal target
6. verify portal sign-in and restricted access behavior
7. confirm public website remains separate under `jonedtransport.com`
8. retire temporary ChatGPT/Sites dependency for the portal only after parity validation

## Acceptance criteria

The migration is acceptable only when all of the following are true:

1. `portal.jonedtransport.com` opens on Azure-hosted private infrastructure
2. Microsoft Entra ID controls sign-in
3. only approved users or groups can access the portal
4. `jonedtransport.com` remains public and separate
5. no real business integration is activated unintentionally
6. current portal UX boundary remains coherent after migration

## Risks to avoid

- collapsing public and private hosting back into one target
- exposing the portal publicly during cutover
- coupling hosting migration with backend activation
- migrating authentication without clear allowlist or group control

## Zero-real-connection confirmation

This package does not connect to:

- Azure SQL real
- Microsoft Graph operational
- SharePoint operational runtime
- Email
- Document intake
- Payments
- Gusto
- PNC
- OneRail
- Frayt
- ELD
- Any other real operational integration

No business automation is introduced.
