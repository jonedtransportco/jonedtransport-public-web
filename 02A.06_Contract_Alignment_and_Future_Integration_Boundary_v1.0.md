# 02A.06 Contract Alignment and Future Integration Boundary v1.0

Version: 1.0  
Lifecycle: Under Review  
Authorization state: AUTHORIZED FOR MOCK-ONLY CONTRACT ALIGNMENT AND INTEGRATION SWITCH READINESS

## Objective

Prepare the JONED Portal Web frontend for a future controlled switch from local mock data to approved real APIs without connecting any operational backend in this phase.

## Alignment decisions

- The contract remains mock-only and fixture-backed in the current phase.
- The canonical base path remains `/api/v1`.
- All domain workspaces now align on a consistent response envelope for success and error states.
- List and detail payloads are normalized so adapters can be swapped without redesigning the UI layer.
- Pagination, filters, search, sorting, empty states, partial responses and error responses follow one shared contract model.
- Role visibility remains interface-only and is not treated as real authorization.

## Normalized payload structure

### List payload

- `items`: `ModuleRecord[]`
- `pagination`: `PaginationMeta`
- `filters`: `FilterDefinition[]`
- `sorting`: `SortDefinition[]`
- `queryState`: `QueryState`

### Detail payload

- `record`: `ModuleRecord`
- `sections`: grouped display-ready detail blocks
- `actions`: `RoleAction[]`
- `partialResponse`: optional `PartialResponseContract`

### Shared operational states

- `ready`
- `loading`
- `empty`
- `error`
- `partial`

## Future switch strategy

- Current mode: `mock`
- Future mode reserved: `api-real`
- Planned switch control: environment flag plus adapter registry plus contract parity checks
- Preconditions for future enablement:
  - approved backend per domain
  - contract parity validation against the normalized payload shapes
  - server-side authorization implementation
  - regression validation for desktop and mobile UX continuity
