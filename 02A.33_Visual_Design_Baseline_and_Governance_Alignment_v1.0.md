# 02A.33 — JONED Visual Design Baseline and Governance Alignment

**Version:** 1.0  
**State:** OWNER-REVIEWED DIRECTION / UNDER REVIEW  
**Workstream:** 02A — Portal Web Frontend Foundation  
**Purpose:** Exportable visual baseline for governed implementation. This package does not replace or modify the approved architecture.

## 1. Design decision

The principal proposal remains the visual direction for JONED Enterprise Platform. It is not necessary to redesign the experience from zero.

The retained characteristics are:

- dark navy, white and yellow JONED visual language;
- cinematic logistics photography;
- high-contrast corporate typography;
- clean cards, operational tables and status indicators;
- separate public website and protected enterprise portal;
- desktop and responsive/mobile behavior.

The original proposal was adjusted only where required to align with the current project structure, security boundary and approved hosting separation.

## 2. Public experience

The public website includes:

- Inicio;
- Servicios;
- Cobertura;
- Nosotros;
- Recursos;
- Contacto;
- Solicitar cotización;
- Rastreo público limitado;
- recruiting routes for Owner Operators and Drivers;
- access to the protected portal.

Coverage remains stated as **México, Estados Unidos y Canadá**.

The public tracking view may expose only:

- valid shipment reference;
- general shipment status;
- safe estimated delivery window;
- instructions to authenticate for authorized details.

The public site must not expose:

- driver names or identities;
- live or historical GPS coordinates;
- vehicle positions;
- detailed routes;
- stops;
- speed;
- operational evidence;
- internal alerts;
- customer-restricted documents.

## 3. Authentication and authorization

The portal is exclusive to Microsoft Entra ID for:

- employees;
- clients;
- drivers;
- administrators;
- other explicitly authorized external users.

No local username/password experience is part of this baseline. The included sign-in screen is a visual simulation only. Real authentication, claims, groups, application roles, session controls and conditional-access behavior remain governed by the approved Azure and Microsoft Entra ID configuration.

Authorization follows least privilege and role-based disclosure. Entra ID is the identity authority; the frontend must not independently grant access.

## 7. Image and identity governance

The logistics photographs were recreated specifically for this design direction and contain no people, public operational data, route labels or third-party logos.

The supplied historical PDF logo was reviewed only as a read-only reference. It is not promoted to normative brand identity by this package. The current clean JONED lockup remains a design placeholder until the active Architecture Office confirms the authoritative brand asset.

## 8. Architecture preservation

This baseline preserves:

- public site and private portal separation;
- the existing `/portal` boundary;
- Microsoft Entra ID as the exclusive portal identity provider;
- current routes for public recruiting;
- the existing API and reporting boundaries;
- the approved Azure review environment and domain-cutover gates;
- all locked payroll/reporting baselines.

This package does not:

- change DDL, data models or calculation logic;
- configure Entra ID;
- create or modify Azure resources;
- enable production domain cutover;
- authorize future modules;
- expose live operational data;
- change payment execution state;
- alter the V140 payroll report design baseline.
